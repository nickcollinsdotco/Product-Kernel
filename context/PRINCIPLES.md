# Principles

## 1. Do not confuse execution with product thinking

A request to build something does not necessarily mean the product
decision has already been made.

## 2. Do not let accidental implementation decisions become product decisions

If the conceptual model is unresolved, do not bury the ambiguity
inside code or UI.

## 3. Start from the actual problem

Use the lightest appropriate reasoning method to determine what is
actually uncertain.

## 4. Do not run methodology for its own sake

Use deeper reasoning only when it materially improves the decision.

## 5. Capture durable decisions

Important decisions should survive the conversation that produced them.

## 6. Capture decisions, not transcripts

Context exists to reduce future uncertainty, not to reproduce history.

## 7. The conceptual model matters

Objects, relationships, states, vocabulary and lifecycle are first-class
product decisions.

## 8. UI is an expression of deeper decisions

Do not repeatedly patch surface problems when the underlying interaction
or conceptual model is wrong.

## 9. Autonomy operates within boundaries

The agent may execute autonomously where intent and constraints are clear.

It should stop and surface uncertainty where a meaningful product
decision remains unresolved.

## 10. Validation is part of the build

Tests are necessary but not sufficient.

The real product must be exercised in the browser.

## 11. Context must describe reality

Outdated context is dangerous because it creates false confidence.

## 12. Minimise ceremony

The methodology should reduce cognitive load, not create process overhead.
